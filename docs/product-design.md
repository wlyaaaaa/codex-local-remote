# 产品设计：Codex Local Remote

## 1. 产品定义

Codex Local Remote 是一个面向个人电脑的自托管浏览器工作台。用户离开
电脑后，只需在安卓手机或其他现代浏览器中打开一个 HTTPS 地址并输入
密码，即可继续使用本机 Codex 项目。

任务执行服务于两个工作目录场景：

1. **注册项目对话**：在电脑本机明确登记的项目根中执行。
2. **无项目对话**：在独立、有界的临时根中执行，不关联项目。

“电脑文件”是与任务 cwd 独立的所有者工具。登录后的浏览器使用同一 Windows
登录用户的管理员后台任务，可管理 Windows 实际允许访问的已检测磁盘；产品
不会再叠加项目、敏感目录或扩展名封锁。普通 ChatGPT / Codex Desktop
始终原生启动；Remote 只通过固定 dispatcher 的显式 Open 建立。受管安全
快捷方式始终请求 UAC，但只是这个 Open 的可选兼容别名。提升只用于特权
控制面与运行代切换；attached Desktop UI 必须由同一用户、同一交互会话的
medium-integrity Explorer primary token 启动，不与管理员后台任务共享
elevated token。

本机 Broker 拥有单一 app-server，Codex Desktop 与 Sidecar 作为两个独立
连接接入。任何一端创建的任务都会被另一端订阅，因此两端使用相同的任务、
轮次和实时事件，不再把 Desktop 对话降级成另一个进程读取的历史快照。

产品不隐藏可用性边界：手机新建任务必须先完成 Desktop 的订阅屏障；
Desktop 不在线时拒绝执行。Sidecar 不在线时，Desktop 仍可独立使用。

## 2. 目标用户与核心任务

目标用户已经在 Windows Codex 桌面端维护多个本机项目，希望使用普通
安卓浏览器完成以下任务：

- 查看电脑上正在进行什么；
- 在已有项目中开始一个新任务；
- 在任务偏离时追加要求或停止；
- 查看是否需要审批以及哪些文件被修改；
- 查看子智能体各自在做什么；
- 判断额度与上下文是否足够；
- 浏览、预览、下载和管理电脑文件。

手机不要求安装应用、扩展或 Tailscale。添加到主屏幕仅是可选增强。

## 3. 成功标准

- 首次登录除密码外没有第二套账号体系。
- 从首页到在已有项目中发出新任务不超过三次主要点击。
- 运行状态、等待审批、失败、断线和完成状态不依赖颜色才能理解。
- 360 CSS px 宽度下没有页面级横向滚动。
- 所有主要触控目标不小于 44×44 CSS px。
- 重连后不会重复插入事件，也不会丢失当前子智能体或草稿。
- 原始协议名和 JSON 默认不可见。
- 用户能一眼区分注册项目对话与无项目对话，同时理解文件页不受该分类降权。
- 验收追求桌面端与手机端的任务语义一致，而不是逐像素复制：同一任务的
  状态、工作摘要、工具活动、文件变更、子智能体和可用动作必须能对应，
  手机布局则按单手触控重新组织。
- 任一端创建的任务在另一端显示相同的任务和轮次 id，不允许双 app-server
  或冷恢复产生第二 owner。

## 4. 功能范围

本章先描述首个公开版本的可交付范围；标注“后续增强”的条目属于产品方向，
不代表当前版本已经实现。

### 4.1 登录与会话

- 产品面向一名本机所有者；电脑浏览器和手机可同时保持两个独立会话，但不
  提供多人角色、权限分级或协同编辑语义；
- 正常只有一端发起控制操作。两端同时提交互斥动作时，先到请求获得执行权，
  后到请求明确返回冲突，不做隐式合并；
- 本机交互式设置一个至少 15 字符的密码或长口令短语；
- 新浏览器输入密码后建立安全会话；
- 查看并退出当前会话；
- 退出全部会话与浏览器内修改密码（后续增强；当前可在电脑本机维护，修改
  密码会撤销旧会话）；
- 登录限速、渐进退避与临时锁定；
- 会话空闲过期和绝对过期。

### 4.2 首页

- 电脑、Sidecar、Codex 与公网入口的分层状态；
- 正在运行的共享对话；
- 来自 Desktop 与 Sidecar 的完整 loaded/active 顶层任务并集；首页不按来源
  过滤，也不以“前三条”截断；
- 最近项目，以及按 Desktop 手工顺序镜像的“置顶 / 最近”对话；
- 额度摘要；
- “新建对话”主行动。

### 4.3 项目

- 从已有线程的工作目录发现项目，但只用于历史归类和展示；
- 只有在电脑本机显式注册的项目根，才可用于新建项目对话；
- 验证目录存在、可访问且未越过允许范围；
- 最近使用；
- 搜索、收藏、Git 分支和工作区状态（后续增强）；
- 在选定项目中创建新对话。

第一版将单一工作目录视为一个项目。多目录项目只在官方协议稳定暴露相应
语义后加入。

无项目对话使用安装时配置的隔离临时根，但该根不进入项目列表。手机既不能
把任意路径直接提交为任务 cwd，也不能把无项目对话提升为注册项目。此限制
只约束任务启动位置，不约束独立的“电脑文件”页。

### 4.4 新建共享对话

- 输入任务；
- 选择本机注册项目，或选择“无项目对话”；
- 从实时模型目录选择模型与支持的思考等级；
- 从运行时权限目录选择权限配置和审批路由；
- 从运行时目录选择协作模式与服务速度档位；
- 创建空任务壳，等待 Desktop 订阅屏障后开始第一轮；
- 自动进入实时对话页。

手机新建流程必须失败关闭。Desktop 未连接、任务壳无法持久化或
`thread/resume` 屏障未完成时，不放行 `turn/start`，页面显示可恢复的具体
原因。

### 4.5 共享对话

- 历史用户消息和助手正文；
- Desktop 已置顶任务的只读标识与顺序；Web 不提供置顶、取消置顶或重排，
  避免与 Desktop 私有状态发生写入竞态；
- 顶层对话列表行提供重命名、复制对话 ID、归档和恢复；元数据 mutation 通过
  登录、同源、CSRF 与幂等门，提交后并发权威回读当前和归档列表；回读失败
  只重试读取、锁定该对话的冲突操作并单独提示刷新状态，不重复已提交的
  mutation；运行中或等待审批的任务必须先停止，归档后立即撤销 Web 管理状态
  并阻止旧订阅重新注入当前列表；
- 流式助手正文；
- 助手公开的工作进展；
- 将 commentary、工具、文件和子智能体活动按原时序组合成可逆 WorkLog：
  进行中的最新段始终默认展开；turn 结束后，短段默认展开、长段默认只挂载
  紧凑摘要，用户一次点击即可恢复全部公开进展与操作；内部 reasoning 不进入
  产品界面，用户消息、最终回答和图片活动保持独立正文；
- 聚合后的工具活动；
- 命令状态与有界输出；
- 文件变更、行数统计和 diff；
- 审批与结构化提问；
- 追加引导、停止，以及独立的稍后发送队列；
- 排队消息的编辑、排序、删除、手动发送与断线恢复；
- 模型、思考等级、服务速度、权限配置和审批路由；
- 任务目标、计划模式；
- 上下文使用、自动压缩提示与空闲共享对话的手动压缩；
- 失败详情与恢复建议。

### 4.6 子智能体

- 运行中、等待、完成、失败和取消状态；
- 父子层级及扁平降级视图；
- 进入任何仍有持久化记录的子智能体；
- 查看它的消息、摘要、工具和文件变更；
- 返回父对话并恢复滚动位置；
- 已完成子智能体不会从导航中消失；
- 子线程只读时，可通过仍可控制的父智能体转交补充要求；
- 连接断开或 turn 身份无法确认时，不显示转交、输入或停止入口。

### 4.7 额度与上下文

- 对话右上角使用一个小型绿色上下文圆环：圆环内只显示当前任务上下文的已用百分比，
  点按既打开详情也立即向 Codex 发起一次新请求，不只展开旧缓存；
- 每个额度窗口的已用/剩余百分比；
- 重置绝对时间统一转换并明确标注为 UTC+8；
- 限制类型、套餐与 credits（服务返回时）；
- 日使用量与累计统计（服务返回时）；
- 当前线程 token 使用和模型上下文窗口；
- 同一详情中显示对话 ID、快照刷新时间、当前实际模型/思考/速度以及权限、
  审批和协作模式；下一轮草稿设置不能冒充当前运行值；
- Codex 实时返回额度不足、rate limit 或 credits 错误时，Web 在同一任务中
  显示阻断提示，而不是只把任务标成一般失败；
- 手动压缩只把 HTTP 接受显示为“已受理”；必须收到压缩项和整轮完成事件才
  显示“上下文已压缩”；
- 自动或手动触发的官方 `contextCompaction` 都显示状态卡片；协议未提供来源
  时不猜测触发方式；
- 缺失数据明确显示“暂时无法读取”，不以 0 代替。

### 4.8 文件

- 文件页以 Sidecar 当前管理员令牌枚举全部已检测磁盘，与当前任务是否关联
  项目无关；
- 文件夹导航、面包屑和当前目录搜索；
- 上传、新建文本文件/文件夹、编辑、重命名、复制和跨磁盘移动；
- 文本与 Markdown 完整复制/编辑，图片和 PDF 在线预览，原文件下载；
- 任务正文中的绝对文件链接使用当前会话内的短时不透明授权打开，不生成
  永久公网裸链；
- 删除默认进入 Windows 回收站；永久删除必须单独选择并再次确认；
- 覆盖默认关闭，发生同名冲突时先停下并要求用户明确选择；
- 不设置项目、敏感路径、隐藏文件或扩展名 denylist；Windows 的实际 ACL、
  加密/挂载状态、文件占用和设备状态是唯一文件权限边界；
- 仍应用传输大小、预览类型和并发上限，并给出明确的权限、占用、消失和
  冲突错误；
- 登录会话、同源、Fetch Metadata、CSRF 和幂等保护覆盖全部写操作。

### 4.9 审计与诊断

- 首版提供不含敏感正文的能力、Desktop/Sidecar/Broker/app-server 版本、
  连接、订阅和降级诊断；
- 登录、退出、创建线程、引导、停止、审批、下载和设置变更的持久化审计
  及按时间、动作、项目过滤属于后续增强；
- 任何版本都不记录密码、Cookie、提示词、回复正文、文件内容或完整命令
  输出；
- 原始协议诊断只允许在本机显式开启且必须有上限。

### 4.10 离线与恢复

- SSE 自动重连和 `Last-Event-ID` 补偿；短暂错误先进入 3 秒恢复宽限，宽限内
  重连不把页面和发送按钮瞬间切成离线；
- 超出内存事件窗口后从 app-server 持久化任务状态恢复；
- 离线保留静态应用外壳；持久化离线浏览已渲染对话属于后续增强；
- 新建任务的首条提示词、项目/非项目选择，以及现有对话输入草稿都只在当前
  浏览器本地保存；创建成功或发送成功后清除，不写服务端审计；
- 排队正文不写浏览器存储；Sidecar 使用 Windows 当前用户 DPAPI 加密后
  持久化，SSE 只发布不含正文的队列摘要；
- 真实断线期间输入草稿仍可编辑、复制和本地保存；若最近已验证 Sidecar 支持
  持久队列，发送按钮可发起一次真实 HTTP 排队请求，只有服务端接收后才显示
  成功；请求失败保留草稿并明确报错。审批、停止和下载等实时动作仍失败关闭；
- 网络切换、浏览器后台切回和电脑睡眠后的恢复。
- 浏览器标签页标题在断线、等待审批、运行和失败时动态提示；不要求安装
  PWA，也不申请系统通知权限；
- Sidecar 重连后补订阅 app-server 已加载任务，不启动第二个 app-server；
- Sidecar 不在线不影响 Desktop 继续使用 Broker；Broker 不健康时明确失败，
  不静默回退到独立 stdio。

### 4.11 生命周期与长对话性能

- 输入草稿、复制对话 ID或打开设置时，不重新解析整段历史 Markdown；
- 对话首次只渲染最近的有界窗口，最上方可逐段展开直到完整历史；最新实时
  消息、命令、文件变更和审批始终位于已渲染窗口；
- 屏幕外消息使用浏览器内容可见性优化；展开更早历史时保持当前阅读位置；
- 实时增量以可恢复事件流为主；会返回完整 transcript 的 `thread/read` 只作
  低频收敛兜底，且用户正在输入时延后，避免长对话每几秒重复解析整段正文；
- 已受理但尚未取得终态的显式操作（例如手动压缩）短暂使用高频收敛，取得
  成功或失败证据后立即回到低频；不能为了省一次读取让界面永久停在“已受理”；
- 新 Web/Sidecar 构建不要求停止 Broker。Desktop、Sidecar 或任一任务生命周期
  仍为 active/pending/unknown 时，Broker 停止操作失败关闭；
- Codex 更新、Windows 重启和睡眠恢复不打开 Remote，也不接管普通 vendor
  Desktop；新安装代以 `-NoStart` 登记，下一次显式 Open 才按精确证据决定采用；
- Desktop Owner Coordinator 是唯一受管 Desktop process owner；原生 Desktop
  永远不依赖一个持久用户环境变量或可能失联的本机端口。
- 受管安全快捷方式使用 `RunAs` 并指向固定 DataDir dispatcher；PowerShell
  控制台保持隐藏。它只代表显式 `Open -AllowDesktopRestart`，不能绑定
  Desktop、源码目录或某个不可变运行代。
- `Interactive` / `Highest` 计划任务中的 coordinator 同时拥有 Broker、
  Sidecar、文件权限和特权控制面；它从同会话 Explorer 的 medium-integrity
  primary token 创建 attached Desktop。任务无触发器、无 catch-up、无自动
  重启；用户主动退出后不自动重拉。
- 显式 Open 必须给调用方一个可感知的结构化最终结果：已连接、无需重启、
  需要一次授权交接、正在修复或失败；受管快捷方式也必须提供等价的短暂反馈，
  且不弹出常驻命令行窗口；
- 状态诊断必须有硬超时并优先读取端口、健康端点和最近启动回执。单个 WMI、
  任务计划程序或 Funnel 查询卡住时返回“该项暂不可读”，不能让整个状态查询
  无限等待。

## 5. 信息架构

移动端底部导航：

1. 任务（合并旧“首页 / 对话”）
2. 文件
3. 设置

桌面端采用三栏：

- 左栏：项目、对话与主导航；
- 中栏：对话和固定输入区；
- 右栏：子智能体、额度、审批与文件检查器。

## 6. 关键交互

### 6.1 新建任务

```text
任务 → 新建对话 → 选择注册项目或无项目对话 → 输入需求
     → 选择模型/思考/权限 → 开始 → 实时对话
```

后台顺序为：

```text
thread/start → 必要时隐藏 thread/name/set 持久化
             → Desktop thread/resume 订阅屏障
             → turn/start
             → 首轮已接受后才让 Desktop 选中任务
```

任一步失败都不放行首轮。成功后 Desktop 与手机展示同一个任务，不创建
“稍后同步”的第二份视图。

### 6.2 共享对话运行中追加要求

运行时输入区提供“发送到当前回复 / 加入下一轮”两个明确语义。前者调用
`turn/steer`；后者写入 Sidecar 队列，不中断当前工作。模型、思考、速度和
权限选择只作用于下一轮，并在输入器中明确显示。

app-server 不提供 Desktop 原生未发送队列的接口，因此 Sidecar 待发送项只在
已登录 Web/手机之间实时同步。队列真正派发并被 app-server 接受后，Desktop
才显示对应用户消息；产品不声称能在派发前镜像到 Desktop 输入器。

同理，`turn/steer` 的当前公开响应只返回 `turnId`。Sidecar 可以确认消息已被
当前轮接收，并在 Web/手机之间即时回显及刷新恢复，但不能要求 Desktop 为另一个
客户端发起的引导创建本地乐观气泡。Desktop 是否即时画出该气泡属于当前 Desktop
实现细节；本项目不伪造未声明的 Desktop 私有事件。普通下一轮和新任务仍走
`turn/start`，被 app-server 接受后按同一任务持久化并在 Desktop 中显示。

队列采用每任务 FIFO 和修订号并发控制。崩溃发生在 `turn/start` 边界时，
先用 `clientUserMessageId` 对账；无法证明已接受或未接受时标记为“状态不明”，
停止自动重试，由用户显式决定，避免重复发送。

连接或 turn 身份无法确认时不显示输入、steer 或停止入口，并明确提示先
恢复连接。

### 6.3 子智能体导航

手机使用缩进列表或全屏页面，不使用横向组织图。进入子智能体后顶部显示
父对话面包屑和只读/可转交状态。

### 6.4 审批

审批使用持久的底部抽屉，而不是一闪而过的 Toast。展示影响范围、具体
变更和 app-server 为本次请求实际返回的全部可选结果。结构化提问显示原始
问题与动态选项；未知的结构化决定失败关闭，不猜测成“允许一次”。默认不
提供永久授权全部操作。若某类审批通知没有携带可提交的决定列表，抽屉仍
显示请求和阻塞原因，但不渲染伪造的同意/拒绝按钮；用户可在 Desktop 处理
或停止当前任务。

## 9. Desktop 兼容性验收

Windows 共享模式依赖 Desktop 当前隐藏的 `CODEX_APP_SERVER_WS_URL`
override，它不是公开、稳定的产品合约。正式受管入口由计划任务中的 Desktop
Owner Coordinator 统一执行，但只有固定 DataDir dispatcher 的显式 Open
可以启动它；普通 vendor 根永远不是 takeover cause。Desktop 必须从同一用户、
同一交互会话的 medium-integrity Explorer primary token 启动；coordinator
基于该 token 创建显式环境，只在受管 Broker 基础就绪时加入本次一次性
endpoint。每次显式 Open 动态发现当前 Desktop 包、随附 app-server 与能力
目录；任何 Remote 故障都必须保留或恢复无 override 的原生 Desktop，不能因
18791 不可达让 Desktop 无法使用，也不能循环重启。

普通 Desktop 更新不要求用户重新配置，也不会自动打开 Remote。下一次显式
Open 在启动 attached Desktop 前比较活动 Broker receipt 与当前包路径/hash/
generation；只有 `Open -AllowDesktopRestart` 才能对精确 native root 执行一次
交接。可兼容 Web/Sidecar 更新在 Broker/upstream/Desktop identity 全部稳定时
先排空 Sidecar 写请求，再只滚动公网层；运行中的任务继续由 Broker/app-server
持有，失败恢复旧 Sidecar。
兼容探测通过才继续，不兼容则原生 fail-open 并在 Web/启动通知中明确显示。
只有出现兼容告警、运行代不匹配或协议行为变化时才触发真实 Windows 增量复验，
不把频繁应用更新变成人工全量验收。发布冻结时至少覆盖：

- Desktop 与 Sidecar 同时连接 Broker，系统中没有第二个独立 app-server；
- 18791 不监听、拒绝连接、身份不匹配或启动超时时，Desktop 仍以原生模式
  正常打开，不能出现 `ECONNREFUSED` 启动失败；
- Broker 在预检通过后、Desktop attach 前退出时，只对本次创建的精确进程
  执行一次原生回退，既有 Desktop 不受影响；
- Codex 更新改变 WindowsApps 路径后，普通 vendor 启动仍原生；固定 dispatcher
  与受管快捷方式无需重建，下一次显式 Open 动态采用当前 Desktop 与随附
  app-server；运行代不匹配时不得把新 Desktop 接到旧 Broker；
- 已连接、无需重启、需要一次交接和失败结果均有可感知反馈，且没有常驻
  控制台窗口；
- 状态命令在有界时间内返回 Broker、Sidecar、Desktop、Funnel、运行代和
  兼容性结果；某个数据源超时只降级对应字段；
- 手机分别创建一个注册项目对话和一个无项目对话，Desktop 立即可见；
- 两端的任务和轮次 id 一致，并实时收到首轮开始、增量和完成事件；
- Desktop 创建的任务也能在手机实时出现并继续；
- 同时存在超过三个运行任务或审批时，手机仍全部显示且可进入处理；
- 运行中从手机分别验证 steer、停止、下一轮排队、动态设置、结构化提问和
  审批；第二浏览器实时收到同一状态；
- Sidecar 重启后加密队列可恢复，边界不明的派发不会自动重复；
- Desktop 缺席时手机新建失败关闭；
- Sidecar 缺席时 Desktop 仍能独立完成任务。
- Desktop 或 Sidecar 连接、以及 active/pending/unknown 任务存在时，默认
  Broker 停止命令必须拒绝且 PID 保持不变；
- 长对话输入连续文字时，历史 Markdown 不重复渲染，命令和文件变更事件仍
  实时插入。

未取得这些证据时，界面和文档只能报告“可用但有限制”，不能把协议层单测
等同于 Desktop 端到端兼容。

## 10. 非目标

- 远程桌面或逐像素镜像原生窗口；
- CLI/TUI 产品界面；
- 公网 shell、任意命令或未经应用认证的裸文件代理；
- 模型隐藏思维链；
- 向公网暴露 Broker 或 app-server 原始 WebSocket；
- 多用户团队协作、云同步或 SaaS 托管。
